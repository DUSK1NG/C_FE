# 编译警告清理与可维护性优化设计

## 背景

当前合并后的 `stage9-results-output` 基线在 C11、`-Wall -Wextra -pedantic` 下功能测试全部通过，但仍有两类可消除的编译警告：

1. Stage1、Stage2 测试和 Stage1 演示程序使用位置聚合初始化创建 `Node`，只填写了 `id/x/y`，导致 `fx` 等后续字段触发 `-Wmissing-field-initializers`。
2. Stage7、Stage10 测试把可写二维数组传给只读矩阵参数。C11 在数组指针携带不同元素限定符时会触发 `-Wpedantic`，尽管调用本身不会修改矩阵。

本次优化的目标是让现有严格编译命令无警告，并提高初始化与测试适配代码的可读性，同时保持当前分支和 FEM 数值行为不变。

## 目标

- 用 C11 指定字段初始化明确表达 `Node` 的全部初始状态。
- 为测试代码提供统一的只读矩阵适配函数，集中处理 C11 数组限定符兼容性。
- 保留生产代码已有公共函数签名、固定容量设计、错误码语义和计算流程。
- 在所有 Stage1–Stage10 契约测试及演示程序中实现 `-Wall -Wextra -pedantic` 零警告。

## 非目标

- 不重写刚度矩阵组装、线性求解、反力计算或结果输出算法。
- 不调整数值常量、容差、矩阵布局或输出格式。
- 不引入动态内存、第三方库或新的运行时依赖。
- 不通过关闭某个警告选项来隐藏问题。

## 设计方案

### 1. 完整初始化 `Node`

在 `tests/test_stage1.c`、`tests/test_stage2.c` 和 `src/main.c` 中，将不完整的位置初始化改为指定字段初始化，并显式给荷载与约束字段赋零值，例如：

```c
Node node = {
    .id = 1,
    .x = 0.0,
    .y = 0.0,
    .fx = 0.0,
    .fy = 0.0,
    .fix_x = 0,
    .fix_y = 0
};
```

这样可以避免结构体字段顺序变化带来的误读，并让测试意图直接可见。已经完整初始化的 `Node` 不做无关改动。

### 2. 统一只读矩阵适配

新增测试辅助头文件 `tests/test_helpers.h`，提供一个 `static inline` 的 `test_readonly_matrix` 函数：

- 参数使用可写矩阵类型，以便 C11 下无警告地接收测试中的本地矩阵。
- 返回生产 API 所需的只读二维矩阵指针。
- 在适配函数内部使用单一、显式的类型转换，集中记录 C11 对数组限定符转换的兼容性边界。

Stage7 和 Stage10 测试在调用 `solve_constrained_system`、`calculate_support_reactions` 时通过该辅助函数传递矩阵；空指针错误路径仍直接传递 `NULL`，保持原有错误覆盖。

该方案不修改生产头文件和公共函数签名，避免为了消除测试编译警告而扩大 API 变更范围。

## 验证策略

实施后按以下顺序验证：

1. 使用 C11、`-Wall -Wextra -pedantic` 编译 Stage1–Stage10 测试和 Stage1 演示程序，确认编译退出码为 0 且无警告输出。
2. 运行全部 Stage1–Stage10 契约测试，确认输出与基线一致并全部通过。
3. 运行演示程序，确认示例几何和刚度矩阵结果保持不变。
4. 如 Docker 引擎可用，执行现有 Docker 构建与运行验证，确认镜像内的严格编译和契约测试也无警告、全部通过。
5. 检查 `stage9-results-output` 分支工作区和分支指针未被修改。

## 风险与回滚

- 风险主要限于测试初始化语法和测试辅助函数类型声明；不触及求解算法。
- 若任一编译或契约测试失败，停止后续集成并回到本优化分支修复；基线分支可直接继续使用。
- 回滚只需移除本次新增的测试辅助头文件及上述初始化/调用点变更，不需要恢复任何生产数据或外部资源。
