# MiniFEM-C：二维桁架有限元求解器总体设计

- 设计日期：2026-08-09
- 设计状态：已获用户确认
- 项目根目录：当前工作区 `c_FE`
- 实现状态：尚未开始，停在 Stage 1 之前

## 1. 项目定位

本项目使用标准 C11 从零实现一个面向土木工程本科生学习的二维桁架有限元求解器。项目的首要目标是把结构力学中的杆系分析、有限元矩阵和数值线性代数连接起来；它不是商业有限元软件，也不调用现成 FEM 库替代核心计算。

第一版只考虑二维线弹性桁架单元，并采用以下假设：

- 小变形；
- 线弹性材料；
- 节点为理想铰；
- 杆件只承受轴向拉力或压力；
- 不考虑弯曲、剪切、温度、动力和几何非线性；
- 使用 `double` 进行数值计算；
- 单位制统一为 mm、N、MPa、mm²。

项目最终应能够读取节点、单元、材料、截面、荷载和约束，完成总体刚度分析，并输出节点位移、单元应变、应力、轴力、支座反力及平衡检查结果。

## 2. 技术路线决策

### 2.1 备选方案

1. **渐进式教学实现**：先用内置模型验证单元矩阵、组装和求解，再增加文件输入、结果导出和更多算例。
2. **输入优先的动态内存实现**：从第一天开始处理文件解析、`malloc` 和任意规模模型。
3. **通用矩阵库优先实现**：先建立较复杂的矩阵抽象，再把有限元算法接入。

### 2.2 选定方案

选用方案 1。第一版使用固定容量数组和稠密矩阵：

```text
MAX_NODES    = 100
MAX_ELEMENTS = 200
MAX_DOF      = 2 * MAX_NODES
```

这样可以把每个阶段的学习重点限定在一个有限元概念上。完成核心功能后，再将固定容量替换为动态内存，并保留现有模块接口。

项目不创建外层 `mini_fem_c` 文件夹，当前 `c_FE` 目录直接作为项目根目录。若模块化实现需要子目录，则只在当前根目录内部使用 `src`、`include`、`input`、`output` 和 `tests`。

## 3. 计算流程

```text
定义或读取模型
    ↓
检查节点、单元、材料、荷载和约束
    ↓
计算每个单元的 L、c、s 和 4×4 刚度矩阵
    ↓
根据全局自由度映射组装 K_original
    ↓
建立 F_original
    ↓
划分自由自由度和约束自由度
    ↓
构造 Kff Uf = Ff
    ↓
带部分主元的高斯消元
    ↓
恢复完整位移向量 U
    ↓
计算单元变形、应变、应力和轴力
    ↓
使用 K_original U - F_original 计算反力
    ↓
检查整体静力平衡
    ↓
输出控制台、TXT 和 CSV 结果
```

原始总体刚度矩阵和原始荷载向量必须保留。边界条件处理使用复制后的矩阵构造缩减系统，不能直接破坏 `K_original`，否则支座反力无法正确计算。

## 4. 二维桁架单元理论

### 4.1 自由度编号

每个节点有两个自由度：

```text
Ux：x 方向位移
Uy：y 方向位移
```

外部节点编号从 1 开始，内部数组索引从 0 开始。对于内部节点索引 `i`：

```text
Ux 的全局自由度 = 2 * i
Uy 的全局自由度 = 2 * i + 1
```

例如，外部节点 3 在连续编号模型中对应内部索引 2，其自由度为 4 和 5。

### 4.2 单元几何

对于节点 `i` 到节点 `j`：

\[
dx=x_j-x_i,\qquad dy=y_j-y_i
\]

\[
L=\sqrt{dx^2+dy^2}
\]

\[
c=\frac{dx}{L},\qquad s=\frac{dy}{L}
\]

若 `L` 小于几何容差，则报告零长度单元错误。

### 4.3 单元刚度矩阵

局部坐标系中的杆单元刚度为：

\[
k_{local}=\frac{EA}{L}
\begin{bmatrix}
1 & -1\\
-1 & 1
\end{bmatrix}
\]

全局坐标系自由度排列为：

\[
u_e=[u_{ix},u_{iy},u_{jx},u_{jy}]^T
\]

对应的 4×4 刚度矩阵为：

\[
k_e=\frac{EA}{L}
\begin{bmatrix}
c^2 & cs & -c^2 & -cs\\
cs & s^2 & -cs & -s^2\\
-c^2 & -cs & c^2 & cs\\
-cs & -s^2 & cs & s^2
\end{bmatrix}
\]

单元轴向变形、应变、应力和轴力分别为：

\[
\Delta L=[-c,-s,c,s]u_e
\]

\[
\varepsilon=\frac{\Delta L}{L},\qquad
\sigma=E\varepsilon,\qquad
N=\sigma A=\frac{EA}{L}\Delta L
\]

规定正轴力为拉力，负轴力为压力。

### 4.4 总体刚度组装

单元连接节点 `i` 和 `j` 时，单元自由度映射为：

```text
[2*i, 2*i+1, 2*j, 2*j+1]
```

对于单元矩阵的第 `a`、`b` 项：

```text
K[global_dof[a]][global_dof[b]] += ke[a][b]
```

这个累加表示多个单元对同一对节点自由度共同提供刚度贡献。组装后的 `K` 表示整个结构的节点力—节点位移关系。

### 4.5 边界条件和线性方程组

总体方程为：

\[
KU=F
\]

把自由自由度取出后形成：

\[
K_{ff}U_f=F_f
\]

第一版使用带部分主元选取的高斯消元法。若主元相对于矩阵尺度过小，则停止求解并提示可能存在：

- 约束不足；
- 结构机构；
- 孤立节点；
- 单元连接错误；
- 总体刚度矩阵奇异。

## 5. 数据结构

### 5.1 Node

节点结构包含：

```text
id
x, y
fx, fy
ux, uy
fix_x, fix_y
```

`id` 是用户输入的正整数编号；`fix_x` 和 `fix_y` 使用 0/1 表示对应方向是否约束。

### 5.2 Element

单元结构包含：

```text
id
node1, node2
E, A
length
c, s
strain
stress
axial_force
```

`node1` 和 `node2` 在输入检查后保存内部 0 基节点索引，输出时通过 `Node.id` 恢复用户编号。

### 5.3 矩阵和向量

第一版使用固定容量的稠密矩阵：

```text
K_original[MAX_DOF][MAX_DOF]
F_original[MAX_DOF]
U[MAX_DOF]
Kff[MAX_DOF][MAX_DOF]
Ff[MAX_DOF]
Uf[MAX_DOF]
free_dof[MAX_DOF]
restrained_dof[MAX_DOF]
```

矩阵和向量的清零、复制、打印等通用操作放入 `matrix.c`，高斯消元放入 `solver.c`。完成固定容量版本并有测试后，再考虑动态内存。

## 8. 分阶段开发和验收

### Stage 1：单元刚度矩阵

- 内容：计算单个杆件的 `L`、`c`、`s` 和 4×4 刚度矩阵。
- 不做：总体求解、文件输入、支座反力。
- 验收：水平杆、竖直杆和斜杆的理论结果正确；矩阵对称。

### Stage 2：总体刚度组装

- 内容：把多个单元刚度矩阵映射并累加到总体矩阵。
- 验收：三角桁架总体矩阵中每个单元进入正确自由度，矩阵保持对称。

### Stage 3：荷载和约束

- 内容：建立总体荷载向量，识别自由和约束自由度。
- 验收：每个荷载和约束都映射到正确的全局自由度。

### Stage 4：高斯消元

- 内容：独立实现带部分主元的高斯消元。
- 验收：2×2、3×3 已知线性方程测试正确；奇异矩阵能停止并报告错误。

### Stage 5：自由度缩减和位移

- 内容：构造 `Kff Uf = Ff`，求解并恢复完整位移向量。
- 验收：三角桁架节点位移与参考结果一致。

### Stage 6：单元后处理

- 内容：计算单元伸长、应变、应力、轴力和拉压状态。
- 验收：三角桁架三根杆的轴力符号和大小正确。

### Stage 7：支座反力

- 内容：使用原始 `K`、`F` 和完整位移计算反力。
- 验收：反力正确，`ΣFx` 和 `ΣFy` 的平衡误差在容差内。

### Stage 8：文本输入

- 内容：读取节点、单元、荷载和约束文件。
- 验收：文件模型与内置三角桁架得到相同结果；非法输入被拒绝。

### Stage 9：结果导出和 Debug

- 内容：输出 TXT、CSV，并通过 `DEBUG` 控制矩阵打印。
- 验收：正式模式输出简洁结果，Debug 模式能看到关键矩阵和向量。

### Stage 10：更多算例和项目整理

- 内容：增加 5～10 节点、8～20 单元的测试结构，整理 README 和项目报告。
- 验收：程序能处理不同规模模型，所有回归测试通过。

## 9. 三角桁架验证模型

### 9.1 模型

节点：

```text
Node 1: (0, 0) mm
Node 2: (1000, 0) mm

```

单元：

```text

Element 2: Node 1 - Node 3
```

```text

```

荷载和约束：

```text

Node 1: Ux = 0, Uy = 0
Node 2: Uy = 0

```

### 9.2 参考几何结果

```text
L12 = 1000.000000 mm
L13 = L23 = 943.398113 mm
Element 1: c =  1.000000000, s = 0.000000000
Element 2: c =  0.529998940, s = 0.847998304
Element 3: c = -0.529998940, s = 0.847998304
```

### 9.3 参考位移

```text
Node 1: Ux =  0.0000000 mm, Uy =  0.0000000 mm
Node 2: Ux =  0.1488095 mm, Uy =  0.0000000 mm
Node 3: Ux =  0.0744048 mm, Uy = -0.3588632 mm
```

Node 2 的水平位移自由，因此不为零是正确结果。

### 9.4 参考单元结果

```text
Element 1: axial force =  3125.000 N, stress =  31.250 MPa, tension
Element 2: axial force = -5896.238 N, stress = -58.962 MPa, compression

```

```text
Node 1: Rx = 0 N, Ry = 5000 N
Node 2: Ry = 5000 N
```

```text
ΣFx = 0
ΣFy = 5000 + 5000 - 10000 = 0
```

## 10. 输入检查和数值稳定性

程序必须检查：

- 节点编号重复或不存在；
- 单元连接自己；
- 单元端点重复；
- `E <= 0`；
- `A <= 0`；
- 零长度单元；
- 非法约束标志；
- 荷载对应节点不存在；
- 孤立节点和可能的机构；
- 高斯消元主元过小。

`config.h` 统一管理最大容量、Debug 开关和容差。几何检查采用长度容差；主元检查采用相对于矩阵尺度的容差，避免直接除以极小数。

## 11. 常见实现风险

重点防止以下问题：

1. 外部 1 基编号和内部 0 基索引混用；
2. 全局自由度顺序错误；
3. 4×4 矩阵符号错误；
4. 组装时使用 `=` 而不是累加；
5. 忘记保留原始 `K` 和 `F`；
6. 高斯消元没有部分主元交换；
7. 用 `== 0` 判断浮点数；
8. mm、m、MPa 和 Pa 混用；
9. 未初始化数组；
10. 矩阵越界；
11. 单元轴力正负号定义不一致；
12. 文件打开失败后继续读取；
13. 动态内存未释放；
14. 结果输出的节点编号与数组索引不一致。

## 12. 测试策略

测试按照“理论单元—矩阵—方程组—结构—输入输出”的顺序进行：

1. 单根水平杆：验证 `EA/L` 轴向刚度；
2. 单根斜杆：验证方向余弦和刚度矩阵；
3. 多单元组装：验证总体矩阵位置和对称性；
4. 独立线性方程：验证高斯消元；
5. 奇异方程：验证错误处理；
6. 三杆三角桁架：验证完整有限元流程；
7. 5～10 节点桁架：验证规模扩展；
8. 非法输入：验证输入检查。

每个阶段完成后，必须先运行本阶段测试，再进入下一阶段。

## 13. 开发环境

目标环境为 Windows、VS Code、GCC/MinGW-w64 和 C11。完整工程编译命令规划为：

```powershell
gcc -std=c11 -Wall -Wextra -pedantic `
    src\main.c src\fem.c src\matrix.c src\solver.c `
    src\io.c src\postprocess.c `
    -Iinclude -o fem.exe -lm
```

运行：

```powershell
.\fem.exe
```

使用 `-Wall -Wextra -pedantic` 提前发现 C 语言问题，使用 `-lm` 链接 `sqrt`、`fabs` 等数学函数。
